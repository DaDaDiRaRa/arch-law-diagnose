> 이 문서는 그중 **아직도 유효한 설계 원칙·가드레일·미착수 분석**만 남긴 버전이다.

## 배경 — 왜 이 방향인가

자매 앱 **arch-law-graph**(법령 지식·RAG·원문 뷰의 주인)와 역할을 나누는 방향을
논의하던 중, 이 앱(diagnose)의 정체성을 더 날카롭게 하자는 결론이 나왔다.

- **diagnose = 결정론적 "대지 판정 계산 엔진".**
  출력은 *숫자 + 판정(RED/YELLOW/GREEN) + 근거 조문 포인터(law_refs)*뿐이다.
- **"이 법조문이 무슨 뜻인가"는 절대 직접 생성하지 않고 graph에 위임한다.** (환각의 가장 큰 진입점)
- graph가 "지식의 주인"이면, diagnose는 "검증 가능한 판정의 주인"이어야 한다.

"날카롭게 한다"의 의미: ① 계산이 더 정확해지고, ② 자기가 모르는 걸 정확히 알고(= 침묵 과대평가 제로),
③ 법 해석 영역으로 새지 않는다.

## 원칙 (지금도 유효)

| # | 원칙 | 의미 |
| --- | --- | --- |
| P1 | **기능 유지** | MCP/API화·기능 경계 재편은 graph 정식 통합 전엔 하지 않는다. |
| P2 | **추가형 우선** | 정확도 작업은 기존 신호·점수·답변범위를 건드리지 않는 추가형으로 한다. |
| P3 | **정체성 ≠ 기능 제거** | "더 날카롭게" = 같은 기능을 더 정확하게. 기능을 빼는 건 graph가 정식 API로 붙는 그때 일. |
| P4 | **환각 표면을 늘리지 않는다** | 정확도를 올린다며 새 추정·새 자동파싱·새 LLM 산정을 들이지 않는다 (아래 "하지 말 것"). |

## 보류 (graph 정식 API 통합 시 착수 — 트리거 규칙: 그 전엔 착수 안 함)

| 항목 | 왜 보류 | 통합 시 할 일 |
| --- | --- | --- |
| **QueryBox 일반 법령 Q&A 축소·graph 링크아웃** | 기능 *축소*다. graph가 API로 안 붙은 지금 빼면 앱이 그냥 나빠진다. | 진단 무관 질문은 graph로 링크아웃, diagnose는 "진단 결과 종속 어시스턴트"로 좁힘. 지금은 일반 질문도 답하되 graph 원문 그라운딩으로 환각만 억제 — 그대로 유지. |
| **confidence로 GREEN→YELLOW 게이팅** | 판정 로직 *변경*이라 "원래 기능"을 건드린다. | `aggregate_confidence` 임계로 GREEN 게이팅. 별도 사용자 결정 후. |
| **MCP/API 도구화 + 계약** | 합치는 단계 일. | 각 계산기를 명시 타입 입출력 도구로 노출. 불변식: diagnose 도구는 숫자+판정+law_refs만 반환, 법령 본문/해석 산문은 절대 반환 안 함. 합친 앱이 law_refs 포인터를 graph `/api/lookup`에 넘겨 본문을 받음. |

## graph 합칠 때 조례/주차/완화 해결 범위 분석 (2026-06-29, 미착수 참고용)

> 핵심: **graph는 "조례가 뭐라 하나(기준 데이터)" 절반을 풀고, "그걸 이 대지에 적용·계산·검증"하는 절반은 diagnose 몫.** 합쳐도 데이터 쪽만 풀린다.
> (graph 보유: 전국 84개 *시* × 조례 4종 본문 + 용도지역→건폐율/용적률·주차·이격·조경·인센티브·심의 기준 추출. 로드맵에 `/api/standard?city=&zone=` 엔드포인트 계획됨. ⚠ graph 정보는 작성 시점 기준, 착수 전 재확인.)

| 항목 | graph 합치면 | 이유 |
| --- | --- | --- |
| **조례 한도** | 대체로 해결 ✅ | graph가 조례 데이터 주인(84개 시 건폐율/용적률 추출 + `/api/standard` 계획). diagnose는 seed 대신 graph에서 받음. ⚠ 84개 *시*만(군 미포함), 추출 실패칸 guard 필요 |
| **주차·심의** | 부분 ⚠️ | graph가 *기준 숫자*(주차 조례·심의 대상 임계값) 제공 → diagnose 산정 입력 정확화. 산정 로직·트리거 발동·실제결과 대조 검증은 diagnose만 |
| **완화·정비 인센티브** | 거의 안 됨 ❌ | 재건축 허용용적률(정비상한·기부채납·지구단위)은 법조문 lookup이 아니라 정비계획·심의 산물 → 규칙 밖. 환각 위험·"확인필요" 유지 |

**빠지면 안 될 점**: graph가 조례값을 줘도 그 추출이 맞는지는 별개(graph도 regex/LLM 추출 → 오류 가능). 실제 케이스로 조례값을 대조 검증하는 캘리브레이션은 graph 합치든 안 합치든 필요 — graph=규모(84개 시) / 실제 케이스=정답 검증으로 상호보완.

## 하지 말 것 (환각 표면 차단 — 영구 가드레일)

- ❌ **조문 의미 설명·본문 인용을 diagnose가 자체 생성** — graph 영역. 새면 즉시 환각원.
- ❌ **가로구역/고시 PDF 자동 파싱** — 폐지고시 오인·환각 위험. 수동 입력만.
- ❌ **LLM이 결정 가능한 수치(건폐율·용적률·주차대수 등)를 만들게 하기** — 룰 계산은 코드로. LLM은 정성(설비·소방)·요약·보조 의견만.
- ❌ **점수 곡선(`coverage.py` 류)을 재설계해 "정밀도"를 흉내** — 임의 휴리스틱을 더 정교하게 보이게 만들면 가짜 정밀도가 된다. 점수는 골든셋으로 캘리브레이션만, 곡선 자체를 새로 발명하지 않는다.

※ 예외: **법제처 DRF 별표 PDF**(현행 시행령 별표, `별표서식PDF파일링크`)는 권위·버전관리 원문이라 OK — 추출값을 seed로 전사 + verify 스크립트로 전수 대조. 고시(행정처분·폐지위험)와 시행령 별표(현행법)를 구분할 것.
